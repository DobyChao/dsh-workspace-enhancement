## 发现：assembly 追加的组件状态被宿主刷新覆盖

复现：新建上述远程会话，发起 `sw_status` 与 bash 只读探针；进入「轨迹」，点开首条
`Current runtime context`。机器清单存在，但 PR 描述承诺的每台机器组件是否生效的状态行缺失。
三轮结束后仍只有这份稳定运行时上下文，没有补入组件行。

与安装宿主磁盘源码交叉核对：

1. 本 PR `src/tools.ts` 在 `systemPrompt.context().text` 中返回机器/工作区信息，随后通过
   `system-prompt/assemble` waterfall 调用 `withRemoteComponentLines` 追加组件行。
2. 已安装的 `@deepseek-ai/dsh-agent-loop@0.2.1-rc.2` 的 `step()` 在真正发请求前调用
   `systemPrompt.refreshContext(assembly, ...)`。
3. 已安装的 `@deepseek-ai/dsh-system-prompt@0.2.1-rc.2` 的 `refreshContext()` 对已注册的同名
   context 再次执行 `resolveContext(provider, context)`；只保留没有 provider 的 waterfall 新增项。
   因此本 PR 对已有 `dsw-session-workspace` 文本的追加会被同步 provider 原始结果覆盖。

影响：模型能通过 `sw_status` 获得组件状态，但没有收到 PR 承诺的组件状态运行时快照。
建议后续修复把缓存探测结果纳入 context provider 求值，并验证真实请求准入刷新后的内容。
本报告不新建待办状态副本，也不替换现有 backlog。
