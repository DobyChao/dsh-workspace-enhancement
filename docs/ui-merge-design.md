# UI 统一设计：连接/机器表单（R2 UI 轮）

> 目标：设置页「远程工作区」的**添加服务器**表单 与 添加工作区 flow 的
> **新建远程连接**表单 行为一致——同一套字段、同一套交互、同一套校验，
> 只有「保存后的动作」不同。本文档是 R2 开工依据，评审通过后照此实现。

## 1. 设计原则

1. **一个表单组件**：`MachineForm`（共享），设置页与 flow 各包一层外壳；
   字段/校验/提示逻辑 100% 同源，改一处两处生效。
2. **字段并集，不留影子**：两套现状里互缺的字段全部合一（见 §2），
   不再存在「设置页有 HostKey、flow 没有」这类差异。
3. **噪音下沉**：日常路径（主机/用户/认证/私钥或密码）平铺；
   高级项（HostKey 模式、keychain、跳板、Passphrase 例外）默认折叠。
4. **两处差异只保留「提交动作」**：Settings = 保存/测试 → 留在表单；
   Flow = 保存并浏览 → 进入该机器目录浏览（与现状一致）。

## 2. 字段并集表

| 字段 | 现状 flow（form.tsx） | 现状 settings（settings.tsx） | 统一后 |
|---|---|---|---|
| 主机名/别名 | ✅ 主机名/别名（别名自动预填） | 主机（纯 IP/hostname） | **主机名/别名**：别名自动解析保留（flow 能力迁移） |
| 端口 | ✅ 必填默认 22 | 默认 22 | 默认 22，必填 |
| 用户名 | ✅ 必填 | 默认 root | 必填，预填 root（可改） |
| 名称 | ✅ 可选（默认 user@host） | 可选（默认空） | 可选；默认 user@host（两处统一） |
| 工作目录/默认工作区 | ✅ 工作目录 | ✅ 默认工作区 | **默认工作区**（统一命名；提示「不填则首次浏览时选择」） |
| 认证方式 | ✅ tabs：私钥文件/密码 | 两个平铺字段 | **认证 tabs**：私钥文件/密码（flow 形态） |
| 私钥文件路径 | ✅（tabs 内） | ✅ | 保留 |
| 私钥口令/Passphrase | ✅ 私钥口令 | ✅ Passphrase | **私钥口令**（统一命名） |
| 密码 | 密码 tab 内 | ✅ 不回显 | 密码 tab 内，不回显；**编辑留空=不变** |
| 加密保存密码 | ❌ | ✅ checkbox | ✅ 高级折叠内（认证=密码时显示；platform 不可用时 encryptFallback 提示） |
| HostKey 模式 | ❌ | ✅ select（默认 accept-new） | ✅ 高级折叠内 select |
| 跳板链 | ✅ 文本（逗号分隔，支持 user@host:port） | ❌ | ✅ 高级折叠内（同 flow 文本，实时校验摘要） |
| ~/.ssh/config 识别 | ✅「识别 ssh 配置」按钮（失焦自动解析） | ✅「从 ~/.ssh/config 导入」列表 | **识别 ssh 配置**（统一入口=下拉列表；失焦/粘贴自动解析保留） |
| 测试连接 | ✅ | ✅ | ✅ 同一 RPC（machines.test） |
| 保存语义 | 保存连接（随后浏览） | 保存（upsert） | 组件只发 payload（machinePayload），动作由外壳决定 |

> 认证 tabs 里要不要第三档「SSH Agent」？dsh-ssh 引擎支持 agent（socket/Pageant），
> 但两现状均无 UI。**R2 不做**（避免扩大面）；agent 机器可通过高级手动配，
> 或另立小轮。→ 待确认（§6）。

## 3. 表单布局（示意）

```
┌──────────────────────────────────────────────┐
│ 主机名 / 别名 *        [识别 ssh 配置 ▾]        │  ← 粘贴/失焦自动解析预填
│ [ prod 或 server.example.com                ] │
│ 端口 *   [ 22  ]   用户名 * [ root         ]  │
│ 名称（可选） [ 默认 user@host          ]      │
│ 默认工作区（可选） [ /home/username          ] │
│                                              │
│ 认证方式   ( 私钥文件 ▸ | 密码 )               │  ← tabs
│ ┌─ 私钥文件路径 * [ ~/.ssh/id_ed25519      ] │
│ └─ 私钥口令（可选）[                       ] │
│ ── 高级（默认折叠）─────────────────────────    │
│  Password（密码）:  [ •••••••• ] ☑ 加密保存(钥匙串) │
│  HostKey 模式 [ (默认 accept-new) ▾ ]          │
│  跳板链（可选） [ bastion,user@jump:2202    ] │
│                                    [ 清除 ] |  │
└────────────────── [ 测试连接 ] [ 保存 ] ──────┘
   （flow 外壳：「保存」按钮文案 = 「保存并浏览」）
```

要点：
- **别名解析行**：填了 alias 且被解析成功后，host/port/user/私钥/跳板自动预填并
  显示一行摘要（「已识别 ssh 配置：user@host:22 · 私钥 ✓ · 跳板 ✓」）。
- **认证 tabs 切换时**：字段区切换（私钥字段组 ⇄ 密码组），不清空对方已填内容。
- **高级折叠**：非展开状态下不占用视觉；展开后按 密码/keychain → HostKey → 跳板 顺序。
- **两处外壳**：Settings 外壳显示机器列表 + 表单（现状布局不变）；
  Flow 外壳显示左侧连接侧栏 + 右侧浏览（现状布局不变）；**仅表单内部替换为共享组件**。

## 4. 交互语义（统一后）

| 交互 | 语义 |
|---|---|
| 失焦/粘贴别名 | 调 `config.hosts`/resolve → 预填 user/port/认证/跳板；未知别名按 IP 处理 |
| 识别 ssh 配置 | 弹出可搜索列表（精确别名，带 user/port/IdentityFile/ProxyJump 标记）；点选预填 |
| 测试连接 | `machines.test`（keychain 机器会真实解析 OS 密码）；按钮 loading + 结果提示（成功/失败消息含脱敏） |
| 保存（Settings） | `machines.add` upsert → 表单清空 + 成功提示（t7 的「已添加」文案保留） |
| 保存（Flow） | 同 payload → 成功后**自动进入该机器目录浏览**（侧栏选中 + 右栏切到远程根） |
| 编辑态 | 载入既有机器的脱敏视图；密码留空=不变；「加密保存密码」取消勾选+输新密码=切明文（R1 语义） |
| 失败 | 认证失败/连不上 → 错误文案（脱敏、可读），不静默 |

## 5. 组件与归属

- 新增 `src/client/machine-form.tsx`：纯表单（字段/校验/别名解析/高级折叠/测试连接按钮）；
  props：`{ mode: 'settings' | 'flow', initial?: MachineView, onSubmit(values), onTest? }`。
- `settings.tsx` 表单区替换为 `<MachineForm mode="settings">`（列表区不动）。
- `form.tsx` 表单区替换为 `<MachineForm mode="flow">`（弹窗/侧栏 shell 不动，
  别名解析逻辑从 form.tsx 迁移进共享组件——注意 form.tsx 现有多级联动，
  逐条迁移时以 flow 现有行为为准归档）。
- `machinePayload()` 函数已有（R1），作为两处唯一 payload 出口。
- 服务端零改动（RPC 端点/字段已就绪）。

## 7. 验收口径（R2）

1. 两处表单字段完全一致（并集表逐项对照截图）。
2. 别名识别/解析预填在两处表现一致。
3. 测试连接：key 机器/密码机器/keychain 机器/错误凭据 四态一致且消息脱敏。
4. 保存后：Settings 清空+提示；Flow 直接进入远程目录浏览。
5. 编辑既有机器：密码留空不变；keychain 取消勾选+新密码 → 明文（R1 语义保持）。
6. 回归：原「选择工作区 → 连接并打开 → 会话创建」不受影响。
7. 无新增服务端依赖；typecheck/build/单测全绿。
