# BUG-21 / BUG-22 — 本机副根上的 sw_exec，以及子代理扫不到项目技能

> 专题事实，2026-10-24。待办在 [`../backlog.md`](../backlog.md)。不是现状架构。

## BUG-21 本机主工作区 + 远程副工作区，围栏档 `sw_exec` 执行前失败

主工作区在本机时，打到远程副工作区的命令只走 `sw_exec`。

`src/exec-tools.ts` 的 `spawnMarked` 调用宿主 `sandbox.confine` 后立刻读 `confined.argv`。lab 宿主 `@deepseek-ai/dsh-sandbox` 的契约是 `Promise<ConfinedArgv>`（`lib/types/index.d.ts`），实现是 `async confine`。官方 bash 会等待这个 Promise。这里没有等。

`shouldPassthroughRemoteConfine`（`src/remote-confine.ts`）只看会话主 cwd。主 cwd 已是 `ssh://` 或占位路径时，`confine` 同步返回带标记的原 argv，远程主会话上的 `sw_exec` 因此能跑。主 cwd 在本机时短路不发生，返回的是宿主 Promise，`.argv` 是 `undefined`，随后按远程 cwd spawn 会在 `argv[0]` 失败。

即便补上等待，本机 runner（bwrap / windows-acl）包出来的 argv 仍会被送到远端。短路要看这次 spawn 的目标 cwd，不能只看会话主 cwd。

`danger-full-access` 跳过 `confine`，所以只有这一档能跑过去。默认的 workspace-write / read-only 过不去。

挂上远程副工作区不会把那台机器写进会话的已连接列表（`session.ws.add` 只 `attach`）。没先 `sw_connect` 时，会先被拒，提示先连接。

验收：本机主工作区、会话为 workspace-write、目标机器已连接。`sw_exec` 指名该机器能跑完，输出来自远端。

## BUG-22 远程会话的子代理扫不到项目 `.dsh/skills`

父会话的工作目录是占位路径（`…\dsw-routes\<id>\…`）。技能扫描用这个字符串，`remoteRouteFromCwd` 能指回远端 `.dsh/skills`，父会话因此能读到。

子代理创建时宿主 `dsh-subagent` 调用 `workingDirectory.set(child, cwd)`（`lib/index.js` 的 `setup`）。`dsh-working-directory` 的 `set` 提交的是 `fs.processPath`，不是传入的占位路径。

`SshFileSystemEngine.processPath`（`src/filesystem.ts` `pathOf`）返回纯 POSIX 路径，例如 `/home/uuz/eee`。没有机器 id，也没有 `dsw-routes`。

技能扫描先做 Node 的 `path.resolve`。Windows 上 `/home/uuz/eee` 变成 `C:\home\uuz\eee`，然后在本机盘上找 `.dsh/skills`。远端那份目录不会被扫到。

用户主目录和宿主内置 skill 不靠项目根，子代理里还在。丢掉的是项目里的 `.dsh/skills` 和 `.agents/skills`。

验收：远程工作区父会话能看到的项目技能，其子代理的技能列表里也有。
