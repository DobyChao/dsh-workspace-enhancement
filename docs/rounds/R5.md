# R5 — I3：会话关联多工作区 + 逐工作区权限

## 目标

一个 session 关联多个工作区：**主 cwd 不变**（不做焦点切换），其他工作区作为**副目录**，
作用是「告诉模型可以把手伸到这里操作」；每个副目录独立权限（`fs` 只读/读写 + 执行开关），
本地与远程目录都参与。需求 ID：**I3**（2026-08-25 拍板修正：焦点切换不做）。

## 拆解

AgentTeams 轮次 `r5-continue-team`（角色：verifier / reviewer / e2e / writer）。

| 任务 | 角色 | 依赖 | 内容 |

| t2 | reviewer | — | R5 代码差异评审 |
| t3 | e2e | — | lab 浏览器 E2E：副工作区面板全流程 |
| t4 | writer | — | 文档同步 + git 提交推送 |

| t6 | reviewer | — | 复评 t2 匹配器修复 |

侦察结论（决定实现路线）：core 的 `session.header.cwd` 不可变、workspace 归属按 `canonical(cwd)`
判定 → 走**插件自持状态 + 混合门面路径路由/权限**，不动 core。

## 遗留

- exec 门为**启动层强制**（文档化边界）。
- 会话栏副工作区徽标延后。
- `detach` 不 prune 空账户由 t5 修复（生产文件里的空键会在下次写操作时自愈）。
- 面板 UI 速写风格（按钮不随主题、面板风格不配合、目录选择器未复用 flow）→ 转入 **R5 三轮打磨**。
- 「副工作区 `fs:只读 + exec:开` 可被 `pwsh`/`bash` 的 `workdir` 命令绕写」由用户实测记录，
  补强方案 a/b/c/d 待拍板（CONTEXT §7）。
- 后续轮引用：R5-polish（UI 抛光 / 浏览方案一）、R6 I18N（面板与徽标文案键化）。
