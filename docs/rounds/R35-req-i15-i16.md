# R35 — REQ-I15 读面降级 + REQ-I16 bash 按工作区注入

- **日期**：2026-09-19
- **需求**：`REQ-I15`、`REQ-I16`（同一 PR）
- **范围**：围栏档核心缺失时的 fs 切流；win32 `bash` 的注册时机

## 目标

缺核心 / 缺 bwrap 时远程会话还能聊天、还能读；写和 bash 继续拒绝。Windows 本地会话不再看见 `bash` 工具，打开 Linux 远程工作区后才出现。

## 拆解

1. **REQ-I15**：`sftpFallbackForCoreGap` 把读面和写面拆开。`CoreRoutingFileSystem.delegate` 只对读面在 `SANDBOX_UNAVAILABLE` 时回 SFTP。Hub 缓存围栏档打开失败（`core.deploy` / `close` 清掉）。spawn 路径不改。ADR-0025 §2.1 / §2.9 取代 2026-09-17 选项 A。
2. **REQ-I16 spike**：上游没有 `tools.update()`。接缝是 `register` / `restrict` + `tools/change`。`Agent.ctx` 在 `agent/created` 上可用（ADR-0021 说的「拿不到」只对 setup 回调）。
3. **REQ-I16 落地**：win32 不再全局注册 `bash`；远程 cwd 的 `agent/created` 注册到 `agent.ctx`。词典描述去掉「本地会报错」。`sectionWin32Bash` → `sectionBash`。

`npm run check:static`、`npm run typecheck`、`npm run test:agent`。新增 / 改写 `test/core-routing.test.ts`（读降级、写仍拒、失败缓存）、`test/exec-tools.test.ts`（本地不注入、远程 `agent/created` 注入）。
