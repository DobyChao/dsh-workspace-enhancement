# R30 — 发布 npm `v0.2.0`

- **日期**：2026-09-17
- **需求**：`PUB-5`（随本轮进 master 的：`REQ-I5` / `REQ-I13`、`INFRA-15`、`BUG-4`、`BUG-6`、`INFRA-16`）
- **范围**：远端「一个核心」+ 核心分发与第三方工具来源政策 + 三个修复 + 打包泄漏修复

## 1. 目标

把已进 `master` 的远端一个核心（`REQ-I5` / `REQ-I13`，ADR-0023/0024/0025）、第三方二进制不再由本仓库
分发（`INFRA-15`）、祖先 jail 修复（`BUG-4`）、核心状态以工件为准（`BUG-6`）与打 tag 前抓到的打包泄漏
（`INFRA-16`）发布为 `0.2.0`。

## 2. 拆解

1. **PR #23**（squash `cf92dae`）：功能 + 0.2.0 版本准备（`package.json`/lock、CHANGELOG 0.2.0 段、
   核心工件版本 `0.2.0-dev → 0.2.0`、UAT R27 结论、backlog 状态）。
2. **PR #24**（squash `8074528`）：打包泄漏修复 —— 打 tag **之前**用真实 `npm pack` 验包时抓到
   `core/dist/staging/`（未打包裸 ELF 4.72 MB + 重复 MANIFEST）会随包发布。
3. tag `v0.2.0`（指向 `8074528`）→ `release.yml` 排队 → 所有者在 `npm-publish` 点 Approve → OIDC 发布。

## 3. 验证

- 功能 PR #23：CI 全绿（ubuntu 22/24 + windows 22；`go test` / `go build` 为权威执行）。
- 打包 PR #24：真实 `npm pack` = **135 文件 / 3.03 MB**，`core/` 只有工件；入口面（`main`/`types`/8 个
  `exports`/`dsh.bundle.patch`/README/LICENSE）逐项在包内；无 `src/`/`test/`/`docs/`/`*.map` 泄漏；
  **负向对照**：退回旧 `files` 写法 + 造 staging ⇒ `pack-smoke` FAIL 并点名路径。
- lab 真机：本轮起 lab 改用 **`npm pack` 的 tarball 安装**（与用户场景一致，不再是 `link:`），
  0.2.0 的核心部署/状态/围栏路径在该形态下走过。
- **发布后 registry 复核**：`latest=0.2.0`；`dist.fileCount=135`（证明发的是修好的打包，不是 137）；
  `dist.unpackedSize≈3.47 MB`；下载包内工件 `MANIFEST.files['dsh-core']` 的 sha256 与实际二进制一致。

## 4. 结果

- npm `dsh-workspace-enhancement@0.2.0` 已发布（OIDC Trusted Publishing，owner 在 `npm-publish` Approve）。
- 宿主窗口不变：`^0.1.5-rc.1`（单家族）。
- **对外行为变更（要写进升级说明）**：
  - 围栏档远程 fs/spawn 走核心（`REQ-I5`）；`/permission` → 核心 `--sandbox`（`REQ-I13`）。
  - **第三方二进制不再随包分发**：`bwrap` 必须由远端发行版提供（核心三层解析，缺失即如实拒绝围栏，
    不崩宿主）；`rg` 远端优先、缺失才由宿主从官方 release 取件并按 pin 校验后随核心推送。
- backlog：`REQ-I5` / `REQ-I13` / `INFRA-15` / `BUG-4` / `BUG-6` / `INFRA-16` → done；新增 `PUB-5` shipped。

## 5. 遗留

- **远端四组合 UAT（有/无 bwrap × 有/无 rg）仍未跑**：缺 `bwrap` 的机器现在会如实拒绝围栏
  （文案含各发行版安装命令与 `danger-full-access` 出路），需要一台干净 VM/容器才能覆盖。
- 新登记：`REQ-I15`（围栏档拆读面/写面：核心不可用时读可见降级，写与 spawn 仍 fail-closed）、
  `BUG-7`（SFTP 与核心的 `version` 算法不一致 ⇒ 中途切模式时读→写 CAS 误报）。
- `ADR-0025` §2.9 记录了「核心缺失时只读静默探测同样 fail-closed」这一拍板（选项 A），
  由此产生的「连纯聊天都进不去」正是 `REQ-I15` 要解决的。
- lab 安装形态自本轮起为 tarball（`AGENTS.md` §3 / `docs/testing.md`）；`npm run build` 不再影响 lab。
