# R56 — PUB-10：准备发布 0.2.5（声明宿主 0.2.1 家族）

> 所有者拍板 **peer-then-release**：先把 `@deepseek-ai/dsh` 0.2.1-rc 家族写成正式支持，
> 再在同一 PR 里把插件与远程组件备成 `0.2.5`。本轮不合并、不打 tag、不触发 npm publish。

## 1. 目标

`PUB-9`（0.2.4）已经发布，backlog 仍停在 doing。本轮把它标 shipped，并准备 `0.2.5`：
peer 联合范围纳入 `^0.2.1-rc.1`，drift 真的安装 0.2.1，版本与 core 同升。

## 2. 拆解

1. **semver**：宿主 `dsh-app-boot@0.2.1-rc.2` 的 boot 检查是
   `semver.satisfies(runtime, range, { includePrerelease: true })`，对照 app-boot 版本。
   旧 pin 因此在 boot 上已匹配 `0.2.1-rc.2`（lab 能过）。npm/pnpm 默认不开该开关，
   `^0.2.0-rc.1` 不满足 `0.2.1-rc.2`。caret 风格沿 UPSTREAM-10：`^0.2.1-rc.1` 覆盖同 tuple
   的 `0.2.1-rc.2`，不含 `0.2.1-alpha.*`。13 个 seam peer 同一条范围；dev 仍 `^0.1.7-rc.2`。
2. **通道**：`next` 现为 `0.2.1-rc.2`（宿主与 13 个 seam 都是），所以 `next` 通道安装 0.2.1。
   `0.2.0-rc.1` 与 `0.1.7-rc.2` 改/留精确版本通道（同一套 `family:` 安装）。三版 registry 都有。
3. **版本**：`package.json` / lock、`CHANGELOG` 0.2.5 段、`core/artifact.json`、
   Go `coreArtifactVersion`、`sync:core-manifest`。core 与插件同升；版本门仍按 major.minor。
4. **待办**：`PUB-9` → shipped，指针 [v0.2.4](https://github.com/DobyChao/dsh-workspace-enhancement/releases/tag/v0.2.4)。
   `PUB-10` doing：合并后 tag + GitHub Release + npm OIDC，所有者 Approve。本 PR 不做这三步。

## 3. 验证

本地 `npm run check:static`、`typecheck`、`test:agent`。core 用本机 Go 重建并登记 sha。
完整 `npm test` / drift boot 由 CI 跑。无新 UI，不跑浏览器。

## 4. 结果

声明与 0.2.5 包装在一个 PR 里。tag、Release、npm `latest` 在合并并 Approve 之后才存在。

## 5. 遗留

- 合并后所有者打 `v0.2.5` 并在 Actions 里 Approve `npm-publish`。本轮不打 tag、不点 Approve。
- 组合基线 `scripts/upstream-baseline.json` 不在本轮重写（scope-watch 仍按旧基线报警）。
- 同 major.minor 不强制重部署。
