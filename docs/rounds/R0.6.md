# R0.6 — dsh-remote 最小合并包

## 目标

把 dsh-remote 的**最小必要能力**并入本插件：TOFU 主机指纹、OS 钥匙串、machines 注册表融合、
3 个 `sw_*` 模型工具 + 一行系统提示、最小设置页；镜像/同步、审计、端口转发、内嵌侧边栏、
更新检查、双 tab 选择器与 23 条旧 HTTP 路由一律**不并入**（统一走 RPC 通道）。
需求 ID：里程碑 1c/1d（CONTEXT §6.1）。

## 验证

- **单测**：15/15（t6 复核记录）；typecheck 0 错误。
- **评审**：t4 **needs-fix**（1 个功能性 BUG：keychain 机器存 `password:''` 使 keychain 密码永不被注入，
  同会话新保存的机器用空密码认证失败）→ t5 修 + 4 单测 → t6 复核「修复全部正确」；
  t3 报 B1–B3（设置页成功提示被覆盖 / 空密码落盘 / auth 标签误判）→ t7 修 → t8 **approve**；
  B4（DPAPI 不可用→静默明文）→ t9 修（后端真实可用化 + UI ⚠ 诚实提示）。
- **E2E（t3）**：迁移 PASS（旧连接文件 → `machines.json`，`c1` 的 id / 私钥路径 / cwd 原样保留，
  旧文件改名 `.bak` 且内容逐字节一致）；TOFU PASS（首次真实连接即写入 `known_hosts.json`，
  `forget` → `machines.test` → 以新 `firstSeen` 重写、指纹一致）；设置页 CRUD PASS；负向断言 PASS。
- **部署验证（1d）**：首启发现真实边界——dsh-remote 遗留的**空 `machines.json`** 挡住迁移 → t10 修复
  （空表放行导入 + 3 回归单测）后重启；最终 `machines.list` → `c1`（`currentId=c1`、`auth=key`）、
  `status` → `connected=true`、`workspace=/home/<user>`、`hostKeyMode=accept-new`、
  `hostKeyKnown=true`、指纹 `<fingerprint>`、`backend=windows`；client.js 133 KB 注入成功。

## 结果

- 交付 `src/hostkey.ts`（TOFU，默认 `accept-new`，三模式，沿用 `known_hosts.json` 路径格式零迁移）、
  `src/credential.ts`（Windows DPAPI / security / secret-tool，含加密回退诚实性标记）、
  machines 注册表融合（`machines.json` 单一真相，`c1` 保 id 迁移 + `.bak` 幂等）、
  3 个工具（`sw_status` / `sw_connect` / `sw_pick_workspace`）+ 一行系统提示、
  `src/client/settings.tsx`（`settings.section` 槽位 order 40）。
- 上线：link 依赖已装入真实 3080，二次重启后运行态验证全绿。

## 遗留

- 五条已知边界（全部转 **R1** 抛光轮）：① 设置页无法把 keychain 机器切回明文（与 dsh-remote 行为一致，
  无安全风险，API `credentialBackend:'plain'` 可绕过）；② `browse.home` 吞连接错误（真实错误由
  `browse.list` 浮现）；③ 失败连接同会话缓存；④ 错误消息含私钥路径；⑤ `registry.test()` 不接 keychain。
- flow 表单 vs 设置页表单字段不一致（CONTEXT §7「UI 一致性」）→ 由 **R2** 统一为并集。
- 决策记录：镜像/同步完全放弃、审计日志砍掉（会话轨迹已能说明）、端口转发延后（→ A4）。
- 后续轮引用：R1（五边界 + 更名）、R2（表单统一）、R4（远程执行）、S1/S2（工具面扩展）。
