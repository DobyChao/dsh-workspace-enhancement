# R4 — I2 + I4 并轨轮

## 目标

① **I4**：远程工作区时保证模型知道自己工作在远程——按会话注入「⚠ 远程 SSH 工作区」认知提示
（本地会话零噪音）；② **I2**：SSH 工作区里的命令/文件/终端按对应系统唤起——把
`ctx.subprocess` / `ctx.fs` 做成**混合 provider**，按工作目录路由本地 / 远程，并打通执行适配、
远程覆盖/编辑修复与诚实性自检。
需求 ID：I2、I4（`drafts/ideas.md`）。

## 验证

- **单测**：134/134（t11 终局；过程中 111 → 122 → 132 → 134，0 fail）；typecheck 0 错误。
- **E2E（多轮矩阵）**：① 认知提示注入 PASS（会话系统提示含「远程 SSH 工作区」+ `user@192.0.2.10`
  + 路径；模型思考文本逐字引述）；①b 本地会话零噪音 PASS；② 远端执行证明 PASS
  （`conn.probe` active + `hostname && pwd` 落远端）；③ flow 写回 PASS；④ 回归 PASS。
- **关键缺陷闭环**：t5 发现**执行适配层损坏**（远程 `pwsh` 每次 exit 127——argv 是 Windows 沙箱
  包装脚本；`write/edit` 报 `cannot get property "sandboxPolicy" without inject`）→ t6 修
  （`forceRemoteSandboxMode` 走官方写路径跳过沙箱包装、fs 经 inject 子纤维修契约、`read`/`glob`
  分世界 + `remoteArgvOf` 重写）→ t7 全矩阵闭环（引擎终端 `bash -c` 落远端 exit 0、远程 fs
  落盘、本地 workspace-write 会话零 override）；t9 又发现 `sw_status` 探针整块被静默丢弃 →
  t10 修（探针追尾 `; true`）→ t11 **approve — 可部署**。
- **真机**：远程覆盖/编辑修复经真实工具链验证（新建 → 覆盖 → edit → 再覆盖全成功，
  远端文件为末版、staging 零残留、本地占位不串）。
- **部署验证**：运行态 `conn.probe` active 8ms、`status` connected、`client.js` 173 KB、TOFU 完好。

## 结果

- 交付：按会话注入的 `sw-remote` 提示 section（全局 section + 从 `context.scope` 反查会话）、
  `src/mixed.ts`（`worldOfCwd` / `worldOfTargetKey` 路由门面，成为 `ctx.subprocess` / `ctx.fs`
  唯一实现）、远程执行适配（`forceRemoteSandboxMode`、`remoteArgvOf`）、
  覆盖发布改 `ext_openssh_rename` + `mv -f` 回退 + `isOwnStagingDirectory` 防御、
  `sw_status` 三行远程环境自检。
- 上线：已部署 3080。

## 遗留

- **已知环境要求**：模型 `pwsh` 工具需远端装 pwsh；`glob` 需远端 ripgrep；终端（bash）开箱即用。
- 远程会话 composer 权限预设显示 **Custom**（旋钮组合 `{full, ask}` 不匹配任何整组）——
  候选方案 A/B/C 待用户拍板（CONTEXT §7）。
- ⑧ 远程 `bash` 工具本轮只做诚实性（127 逐字报告），真正补注册留给 **S2**。
- 后续轮引用：R5（副工作区权限门复用混合门面）、S1/S2（`sw_exec` + win32 `bash`）。
