# R0.5 — dsh-ssh 精简版独立落地

## 目标

把上游 dsh-ssh 精简后独立落地为新包 `dsh-workspace-enhancement`：删除死代码、提取共享核心、
修复上游硬编码的主机校验接线。本轮**不**纳入 dsh-remote 功能（整体移到下一里程碑）。
需求 ID：里程碑 1a/1b（CONTEXT §6.1）。

## 拆解

AgentTeams 轮次 `dsh-ssh-slim`（角色：engineer / tester / reviewer）。

| 任务 | 角色 | 依赖 | 内容 |
|---|---|---|---|
| t1 | engineer | — | 移植并精简 dsh-ssh 核心到本仓库（源码级） |

| t6 | engineer | — | 清理 nit①：移除 `dsh-invariants` 死依赖并复验构建 |

关键重构：提取 `src/ssh-core.ts`（`runtime.ts` 532→263 行、`connection.ts` 365→176 行）、
`src/listing.ts` 共享 `listRemoteLevel`（picker / web 去重）、`hostVerifierFor` 单一实现、
registry 连接把 `strictHostKeyChecking` / `knownHosts` 接线（默认关，修复上游硬编码 `false`）。
删除：`filesystem-routed.ts`、旧单连接版 `filesystem.ts`、`invariant.ts`。

- **E2E（t3 + t5）**：lab 50599 + browser-use 0.13.8，全流程 PASS——
  新建连接（`user@192.0.2.10:22` 真实 SSH 握手）→ 测试连接成功 → 保存 → 远程浏览 `/home/<user>` →

## 结果

- 交付可 build 的插件骨架：`lib/`（host）+ `lib/client.js`；`cordis.patch.yml` 三行组合
  （`ssh-remote` / `directory-picker-ssh` / `ssh-web-channel`，并禁用 `directory-picker-auto` 默认行）。

  三种模式（前台 / `-NoBoot` / `-Smoke` 全自动自检+停服）。
- 上线：R0.5 已部署到真实 3080 实例（profile 备份 `%DSH_HOME%\profiles\web\package.json.bak-<timestamp>`），
  并写出 `scripts/restart-3080.ps1`（会话外执行：PID 探测 / 日志 / 三项验证 / 回滚提示）。

  真实 home 零改动，key 未写入任何日志）。
- nit②（`dsh-ssh:` 前缀 / RPC 渠道名 / 状态文件名更名）→ 由 **R1** 承接。
- nit③（`terminal.ts` 的 `cd` 无 `--`）→ 未处理，保持上游原样。
- 沙箱 npm 未执行 `ssh2` / `cpu-features` / `esbuild` 的 install 脚本（警告非错误，走纯 JS 回退）；
  生产构建需批准。
